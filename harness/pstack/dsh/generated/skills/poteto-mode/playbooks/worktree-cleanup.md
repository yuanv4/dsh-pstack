### Worktree and simulator cleanup

1. Snapshot and audit. Record free space on the relevant volume with a platform-appropriate tool. Run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` only when the script and a compatible shell are available. Without `-b` it checks `MERGED` against `origin/HEAD`; pass `-b origin/<branch>` for another base. Otherwise audit the paths from `git worktree list` for size, age, merge state, uncommitted work, PR state, and recent chat usage. Background a slow transcript scan.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar. Pick each subagent's reasoning effort for the job, per the Subagents section. Use a supported per-call effort when needed.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. Verify each resolved absolute target path is the intended worktree from `git worktree list` before any deletion. Run `git worktree remove --force <path>`. If ignored artifacts remain, verify the absolute path again before removing the directory using the native platform command, then run `git worktree prune`. Branch refs survive; uncommitted files do not. Record free space and re-list worktrees.
6. On macOS only, and only when `xcrun` and the relevant simulator tools are available, inspect simulator devices and runtimes before deleting the confirmed unused items. Inspect Xcode caches and other package caches as needed. Verify each resolved absolute target path before deletion. Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** free space on the relevant volume before and after, the worktrees pruned, and a one-line reason for each held back.
